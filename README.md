# OAI-Adversarial Plugin（O/对抗插件）

## 开发说明与声明

- 本插件由 **DeepSeek「大肥鱼」** 进行编程开发；
- 存在潜在的 bug 与问题属于正常现象，本项目主要用于提供实现思路；
- 欢迎在遵循开源许可（MIT）的前提下进行二次开发。

---

面向 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) 的自研插件（内部 ID：`timezone-override`），聚焦 Codex / ChatGPT 上游请求链路的三类能力：**请求时区规范化、上游模型一致性监测、X-Codex-Turn-State 的观测与有效值覆写**。

> ⚠️ **重要提示（务必先读）**
> 本文中「**292 字节**」是本项目在特定账号与套餐下观察到的**有效状态长度基准**。不同账号、地区、套餐或上游策略下，有效字段长度可能不同——我们也曾观察到 **312 字节的风控降级态**（模型响应一致但状态被降级）。
> 因此：**探测验收规则（模型一致 + 长度）需要按你自己的实际观测调整**，请勿直接假设 292 就是唯一正确答案。调整位置见「验收标准」一节。

## 功能特性

### 1. 请求时区规范化（原始功能）
对发往 Codex 上游的请求体做时区处理：检测 `<environment_context><timezone>…</timezone></environment_context>` 块，将原时区替换（或缺失时补入）为目标时区（默认 `America/Los_Angeles`），支持 Responses / Chat Completions / Claude 格式与 WebSocket 通道。

### 2. 上游模型一致性监测
捕获上游实际返回的模型名，与入站请求模型比对；不一致的记录在面板醒目打标（类 sub2api 的「模型不一致」提示）。

### 3. X-Codex-Turn-State 全链路观测
对每条请求记录该字段的**长度**、**来源**（请求 / 响应 / 流 / 探测轨）、**完整值**（4096 字节上限）与**短预览**，并通过 Fernet 内嵌时间戳计算剩余有效期。

请求注入与响应学习分别记录。插件读取上游原始响应的 `X-Codex-Turn-State`，确认响应模型一致、长度符合配置策略后，按原请求绑定更新该账号/模型的双槽。使用中票据仍有效时，新票据进入预备槽；没有有效使用中票据时直接成为使用中票据。相同票据不续期，签发时间可解析时拒绝过期及不比现有槽位更新的票据。长度规则是经验策略，不是票据签名验证。

流式响应先缓存原始票据头，取得响应模型后再接纳；后续回调携带插件修复后的头时，不把修复值当作上游新票据。请求记录显示实际结果：票据相同、已更新使用中/预备票据，或未接纳原因。插件收到的响应头没有票据时显示“未收到票据”；当前 WebSocket 事件接口不提供响应头时显示“宿主未提供响应票据头”。这些情况都不能证明上游一定没有签发票据，也不能用模型正常推断票据已续期。

### 4. 请求侧覆写（健康基线优先）
将匹配模型的请求头 `X-Codex-Turn-State` 替换为有效值：
- **健康基线优先**：每个账号凭证/模型维护独立基线，恢复有归属的快照，由该账号业务流量与指定账号探测刷新。
- **不跨账号兜底**：客户端票据不能仅凭长度认定归属；使用本账号有效基线，无有效基线或身份未知时清除客户端票据，不借用全局静态值或其他账号票据。
- **账号级隔离**：通过宿主选中的 AuthID/index 与 Host Auth 凭证回调绑定账号身份；同名认证文件替换后不能复用旧身份票据。独立于实验性路由开关。
- **到期续期**：票据 TTL 到期只显示待重探，不标记账号降级。账号路由与自动选号探测启用时，每 30 秒独立扫描到期账号，不依赖业务请求或提前预备窗口。按账号、模型、本次到期时间分别排队，一份到期票据最多一次自动尝试，执行前持久化去重；失败可手动重探，重启不重复已尝试票据。遵守停止/暂停/禁用，探测异常与真实业务异常分开记录，账号级拒绝遵守面板总开关。
- **会话来源守卫**：额外按会话、票据指纹和账号/模型记录短期来源。`observe` 记录，`enforce` 增加已知异账号/异模型防护；两种模式均不放宽上述凭证级隔离。未知票据不能直接写入账号池，须由成功且模型一致的响应确认。
- **传输边界**：HTTP 与 SSE 可在响应模型确认后建立归属；当前 CPA 插件 ABI 不向插件暴露 WebSocket 握手响应头，因此 WebSocket 仅执行请求侧来源检查，不能据此声称已确认响应票据归属。

### 5. 手动探测轨
「开始探测」启用自动预备并排队一轮任务；所有入口共用一个串行 worker，等待任务按模型配置顺序优先执行，同一模型优先级内保持先进先出。健康值仍充裕或已有有效接班值的模型会跳过。获得模型一致且长度符合的 state 后才更新对应槽位。

优先模型在其他模型重试期间入队时，当前请求完成并经过串行间隔后让位，无需等低优先级模型耗尽整轮次数。被让位任务保留已耗尝试次数、出口预算和轮询位置，之后继续剩余任务；暂停或停止仍会取消对应任务，不因插队重新启动。优先级取自 `models` 顺序，与面板“优先探测模型”一致。
- **luna / terra 不检测**：直接请求这两个模型家族时，不判断 state 长度或响应模型一致性，不进行降智拦截、静态/健康基线注入或异常 state 回灌。自动与单模型探测均跳过，面板显示“不检测”。原始响应模型和长度仅作为请求记录保留；旧失败、疑似和业务异常标记不再影响这些请求。
- **按原始请求判断**：优先采用 `requested_model`，缺少时采用 `model`；不能因为 astra/sol 的响应变成 luna 而豁免原请求。支持 `gpt-<版本>-luna/terra` 及带后缀的模型名，按名称分段匹配，不误匹配 `lunafoo`。
- **停止当前轮**：取消当前排队与在途探测，保留自动预备原状态；在途请求在尝试边界结束，临近到期的模型可在后续扫描中重新排队。
- **停止全部**：取消当前任务并停止自动预备，重启后保持停止，直到再次点击「开始探测」。旧 API `stop-round` 保持停止全部语义，新 API 为 `stop-current` / `stop-all`。
- **代理池轮询**：`direct` / `socks5` / `http` 出口按序轮换；轮换池（`# pool:`）享有独立的**池探测预算**（`pool-attempts`，默认 100 次）：普通出口仍按每出口 `attempts-per-proxy` 次，而池子每轮最多可抽 100 次全新源地址的奖，自动单轮上限 =（普通出口数 × 每出口次数）+（池子 × 池预算）；
- **验收规则**：模型一致 + 有效长度（默认接受 292 / 332 字节）才算成功；
- **降智请求拒绝**：全局独立开关（默认开启），仅适用于参与检测的模型。业务流量自身确认的异常仍按开关拦截；探测轨的失败或疑似降智只有在请求没有可用健康基线时才参与拦截判断。旧值仍有效或已有有效接班值时，预备失败不会使业务请求收到 403。429 限流不计入降智。
- **失败标注与业务分离**：探测失败保留诊断记录，现有健康值继续服务；自动预备是否重试取决于预备开关、模型暂停、有效接班值及 90 秒节流，不以失败徽标判断业务值是否失效。

### 6. 状态路由台 UI
CPA 管理面板内三个标签页：请求记录、状态路由台（模型健康基线 TTL 进度、手动探测控制、探测轨迹、失败徽标、来源提示）、**代理池**（出口总数/可用/冷却·轮休中统计，每个出口的状态、连续失败次数、冷却或轮休至（UTC+8）、剩余时间与最后错误）。账号健康路由区按脱敏 AuthID 展示各账号独立的票据剩余时间，并汇总会话守卫模式、异账号观测、替换和剥离计数；请求记录显示来源分类和短指纹，不在来源日志中记录完整 state。标题右侧常驻「降智请求拒绝」开关，各标签页均可见。

### 7. 出口池熔断与轮休（IPv4/IPv6 混合友好）
探测轮询会在出口间轮换；**未获得正确 state token 的普通出口**（长度异常、模型不一致或连接类错误）连续失败达到阈值后，被**短暂移出池子**并进入 `exit-cooldown-minutes`（默认 180 分钟）冷却，到期后自动回归；而**成功获取一次健康状态后也会轮休** `exit-success-cooldown-minutes`（默认 30 分钟），让后续尝试优先分散到其他出口，避免同一地址持续高频使用。两类出口：

- **普通出口（固定端点）**：成功轮休（30 分钟，设 0 关闭）；`exit-fail-threshold`（默认 3）次连续失败进入冷却；
- **轮换池（`# pool:` 标记，一个端点背后是大量可轮换源 IP，例如本地 IPv6 /64 动态代理）：永不冷却 + 独立探测预算** —— 每次连接都会换一个新源地址，"这次抽到坏的"只反映当前上游状态，不代表池子坏了；失败计数继续累计（供面板观测），健康捕获清空计数，但不会把池子雪藏 3 小时。每轮尝试额度也单独计算：池子享有 `pool-attempts`（默认 100）次抽奖机会，优先与普通出口轮询混合取样，份额用完后继续深潜自己的剩余预算；普通出口保持 `attempts-per-proxy`（默认 3）次/出口的小份额。自动单轮上限 = Σ（普通出口×3 + 池预算）。`exit-pool-fail-threshold` 仅为旧配置向后兼容保留，不再参与判定；`max-attempts-per-round` 显式设置时仍然全局覆盖。

在 proxies 文件中用行尾标记声明池成员：

```
direct
socks5h://192.0.2.1:1080   # pool:ipv6
```

面板「代理池」标签页会把该出口显示为「**IPv6 池**」（或标记里声明的名称）；**探测轨迹**对 socks5 出口还会显示本次连接实际使用的源地址（服务端 BND.ADDR 回报，聚合池下每次不同）。升级时自动做策略迁移：轮换池的任何历史冷却立即解除。

### 8. 预备接管（无感换 token）
面板按模型显示汇总状态，默认折叠账号详情；展开查看 CPA 已启用账号的邮箱与独立票据，邮箱默认隐藏为 `***`。至少一个账号有可用基线就显示“可用”，全部无可用基线则显示“不可用”。CPA 禁用的账号从当前列表隐藏，重新启用后同步显示，旧槽位保留。插件不再因探测失败冷却账号，旧账号冷却参数不再生效；串行间隔、探测预算与代理出口轮休保持。

每个 **账号 × 模型** 独立维护 **两个槽位**：当前 active 值 + 提前备好的 candidate 接班值。N 个账号、M 个参与检测的模型，最多维护 `N × M × 2` 个槽位，按实际捕获按需创建。luna/terra 等不检测模型不维护有效票据。

**票据严格绑定账号，不能跨账号共享或兜底。** 通过 CPA 选定账号后的 `selected_auth_id`、`selected_auth_index` 和 Host Auth 回调读取的凭据身份共同确定归属，同一请求重试换账号时重新匹配。检测到同名认证文件换账号后，该认证项在当前进程内隔离，重启 CPA 后重新绑定；更换账号应停止 CPA 后操作，不能把 after-auth 的客户端头当作上游身份。相同 JWT 主体和工作区的 Token 刷新保留归属，不透明 Token 更换需要重启重新绑定。客户端带来的票据即使长度正常，也不能证明属于当前账号：有本账号有效票据时替换，没有时清除或置空该请求头、不注入其他账号票据。未识别账号时同样不借用票据。旧版未记录账号归属的票据与全局静态 `value` 不自动绑定给任何账号；它们保留为历史数据，不参与账号票据回灌。

- **一个健康值就够**：一旦获得有效状态值，系统就安静等待，不会在远离到期时反复探测；
- **临近才预备**：自动预备开启且模型未暂停时，active 剩余有效期进入 `prefetch-minutes`（默认 3 分钟）窗口，看门狗每 30 秒巡检并排队；每个账号/模型组合有 90 秒节流，已备好有效接班值时不重复。窗口是触发时机，串行队列等待与上游失败可能导致来不及取得新值；
- **平滑接手**：成功获得的新值先停在接班槽；业务继续使用旧 active，到期后的业务取值、状态读取或预备扫描会在锁内提升有效接班值。若已备好仍有效的接班值，业务无需等待新的探测；没有接班值时不能保证连续覆盖；
- **重启与新旧值保护**：快照恢复 active、candidate 和停止全部状态。重启不主动替换仍有效的 active；重复值、较旧值与已过期的新捕获不能覆盖较新的接班值，旧快照中无续期能力的重复接班值会被清除；
- **手动轮自动跳过**：“开始探测”只探测尚未持有健康值（或已临近到期）的模型，仍在有效期内的模型直接跳过（运行备注会说明），需要强制刷新单个模型时用行内的 ⟳ 按钮；
- **关闭提前预备**：`prefetch-minutes: 0` 关闭提前预备，不关闭账号到期扫描；停止全部或关闭探测总开关可以停止自动探测；
- 面板上出现绿色「预备就绪（剩余 xx）」徽标即表示该模型的下一任 token 已停当待命。

状态路由台支持输入“提前预备”分钟数并点击“确认保存”。只接受非负整数且小于 token 有效期，`0` 关闭后续自动预备；当前已经排队/执行的任务不因此取消。保存成功后后续扫描采用新窗口，仍遵守模型暂停、全局停止、有效接班值和重试节流，不会自动点击“开始探测”。输入中的草稿不被后台刷新覆盖，保存失败保持原设置。窗口较大可以给较慢的代理池留出时间，但预备 token 等待接管时也消耗自身有效期。

状态路由台还支持输入“串行间隔”秒数（`probe-interval`，1–3600）并点击“确认保存”。它同时控制同一模型的重试间隔与跨模型排队节奏：保存后从下一次间隔等待开始生效；已经开始的等待（含在途请求之后的等待）按原值结束，不会重置当前计时器。保存不会重启任务、解除全部停止或模型暂停，也不会自动发起探测；写入 `runtime-settings.json` 后在重启后保留。输入中的草稿同样不被后台刷新覆盖，保存失败保持原设置。

探测设置新增“每日休眠（UTC+8）”：起止小时均为 0–23 的整数，默认 0～0；起止相同表示关闭，支持跨午夜（如 23～7）。时段为左闭右开，例如 2～7 在 UTC+8 02:00 起不再发起新探测，07:00 结束。保存到 `runtime-settings.json`，不受服务器/Docker 本地时区和夏令时影响。

休眠优先于自动预备，手动发起、模型恢复及已经排队的探测同样等待；在途请求可完成，保留已有票据、排队任务和当前轮已耗预算。结束后未完成任务继续，自动预备按原规则在后续扫描（最多约 30 秒）触发；不解除全局停止或模型暂停，也不把 0 窗口变成自动模式。正常业务请求及已有候选票据接管不因休眠而暂停。API 使用 `sleep-hours`，必填 `start_hour` 与 `end_hour`；保存失败保持旧设置。


### 9. 代理入口新增、编辑与热加载

代理池页面可以新增单代理或 Pool 聚合代理入口，并编辑名称、地址、认证、类型、每轮基础次数和探测次数倍率。支持 `socks5`、`socks5h`、`http`、`https`，需填写有效端口；`direct` 的地址不可修改。Pool 指已有的聚合服务入口，背后的服务负责轮换出口 IP；仅修改类型不会把静态代理变成轮换服务。

- 每轮基础次数为 `0` 时继承全局 `attempts-per-proxy` / `pool-attempts`；实际预算为基础次数乘以倍率并向上取整。例如聚合池基础 100 次、倍率 2，预算为 200 次。
- 倍率支持 `0.01–100`，每个出口每轮最多 1000000 次。倍率影响尝试总预算，不改变优先级串行 worker，也不改变份额内轮询顺序。显式 `max-attempts-per-round` 仍优先限制整轮总次数。
- 保存成功后热加载，不启动新任务、不解除停止或暂停。已选定的在途尝试允许结束，后续尝试采用新地址/类型/预算；按稳定出口 ID 扣除本轮已消耗次数，编辑或增加预算不会清零已经消耗的次数。
- 编辑地址/认证保留该出口的禁用状态和冷却统计。改为聚合池时解除与聚合池规则不符的冷却，保留失败计数；单纯修改名称、预算或预备时间不会清除统计。
- 编辑时用户名和密码留空保留原值；清除认证需要显式勾选。密码不回显，管理摘要和探测活动中的代理地址移除认证信息，操作通过不含凭据的出口 ID 定位。

面板设置同步写入状态目录旁的 `runtime-settings.json`（原子替换、权限 0600），写入成功才更新运行配置；无需重启。面板设置优先于 YAML/出口文件，未编辑的入口继续沿用配置文件，已编辑及新增入口由面板保存值覆盖并在重启后保留。若以后缩短 token TTL，实际预备窗口会限制为新 TTL 以下。运行设置与票据快照分开存储，备份/迁移时须同时保留；文件损坏会显示错误，不会静默覆盖。配置热重载不清空票据；进程重启仍先恢复 `state.json` 中有效的 active/candidate 和停止模式，再进行预备扫描。

管理接口新增 `prefetch-window`（`minutes`）、`probe-interval`（`seconds`，1–3600）和 `save-exit`（`exit` 对象：`id`、`url`、`label`、`pool`、`attempts`、`multiplier`，可选 `username` / `password` / `clear_auth`）。新增出口不传 `id`；编辑使用状态摘要返回的 `id`。`exit-enabled`、`reset-exit` 也支持 `id`，保留旧 `proxy` 参数兼容。

## 架构总览

```
业务轨（正常流量）:
  Code Desktop / API Client
     └─► CPA (:8317)
           ├─ 时区规范化
           ├─ Turn-State 注入（仅本账号/模型健康基线）
           └─► 既有代理出口 ──► Upstream (chatgpt.com/backend-api/codex)

响应轨（先观测原始票据，再按需修复）:
  Upstream 响应携带 X-Codex-Turn-State
     ├─ 模型一致 + 长度符合策略 → 本账号双槽比较，相同不续期，新票据按规则入库
     └─ 长度不符 / 模型不一致 → 按既有规则向下游注入本账号健康基线

探测轨（手动触发 + 临近到期自动预备，独立 egress 池）:
  状态路由台「开始探测」/ 自动预备扫描
     ├─ 按优先级逐模型尝试（可随时停止）
     ├─ egress 池轮换：direct → socks5 → http proxy
     ├─ 验收：模型一致 + 长度符合配置策略
     └─ 通过 → 写入 active 或接班槽；失败标注，不影响仍有效的业务基线
```

**插件钩子**（CPA 插件宿主能力）：
`request.intercept_before` / `request.intercept_after`（请求覆写）、`response.intercept_after`（非流式观测）、`response.intercept_stream_chunk`（流式观测）、`websocket.response_event`（WS 观测）、`management_api`（面板路由）。

## 工作原理

### Turn-State 是什么

`X-Codex-Turn-State` 是上游在响应头下发、客户端在后续请求回传的**会话粘性状态**，用于连续性/缓存亲和。其值为 **Fernet 认证加密 token**：

```
[1B 版本 0x80][8B 大端 Unix 时间戳][16B IV][160B 密文][32B HMAC-SHA256] = 217 字节（base64url 后 292 字符）
```

- 内嵌时间戳可用于估算有效期（本项目默认 TTL 55 分钟）；
- HMAC 覆盖全部前置字段：**任何字节级改动（包括改时间戳）都会破坏签名**，密钥在上游侧，本地无法重新生成合法 token；
- 因此覆写策略是「**复用一个曾由上游签发的真实值**」，而不是改造/伪造。

### 探测轨状态机

```
自动预备待命 ──(未暂停且剩余 TTL ≤ 窗口)──► 排队 ──► probing
probing ──(验收通过: 模型一致 + 配置长度B)──► 接班就绪（旧值继续服务，到期取值时原子接管）
probing ──(单轮达到 max-attempts)──► failed（标注: 次数/轮数/最后错误/时间）
停止当前轮 ──► 正在停止 ──► 原预备模式（保持健康基线）
停止全部 ──► 正在停止 ──► 全部停止（重启保持，开始探测恢复）
```

### 覆写决策链

```
CPA 已确认当前实际使用的账号?
 ├─ 否 → 不注入，清除客户端携带的未绑定票据
 └─ 是 → 当前账号/模型存在有效 active 或可接管 candidate?
         ├─ 是 → 仅注入该账号的有效票据 (applied)
         └─ 否 → 不注入，清除客户端票据；不能借用其他账号或全局静态值

响应侧（非流式 / 流式；WebSocket 仅归属明确时记录异常）:
 已知账号归属且模型一致、长度符合配置策略 → 写入该账号/模型槽位
 异常响应 → 只记录该账号的异常；回灌也只能使用该账号自己的健康基线
 无法确认原请求账号 → 不归档为任何账号的票据、不回灌
 Usage 只有 AuthID，不用它单独捕获票据，以免认证文件替换后的迟到事件串账
 luna/terra 等不检测模型仍遵循原豁免，不改写其票据

账号路由开启时的会话来源守卫:
 客户端 state 已知属于当前 AuthID + 模型 → 允许按当前覆写策略处理
 客户端 state 已知属于其他 AuthID / 模型 → observe 只记录；enforce 剥离或用当前账号健康值替换
 客户端 state 来源未知 → 不写入账号池；账号隔离仍只注入当前凭证的健康基线

响应侧（非流式 / 流式；WebSocket 只观测模型）:
 上游返回的 X-Codex-Turn-State 长度异常或模型不一致?
 ├─ 是 → 丢弃该值，向下游回灌健康基线（未回流污染）
 └─ 否 → 符合配置长度且模型一致 → 写入该账号凭证/模型槽位
```

## 验收标准与长度说明

### 当前实现

探测成功 = **HTTP 200 + 模型响应一致 + 长度属于 `accepted-state-lengths`**（三条缺一不可）。
不符合配置列表的长度视为疑似异常，判定失败并继续重试换 IP。

### ⚠️ 为什么 292 需要按你的环境调整

- 292 字节 = 217 字节 Fernet 结构（160 字节密文恰好是 16 的倍数），这是**本项目观测到的健康值形态**；
- 我们曾在同一模型上观察到 **312 字节**（224 字节解码、密文非 16 倍数，结构异常），且出现时上游行为异常——因此判断为**风控/降级态**；
- **不能保证所有账号/套餐的有效字段都是 292 字节**。如果你在自己的环境观测到不同长度始终一致地伴随正常响应，请调整验收规则。

### 如何调整

在插件配置中设置验收长度，无需修改源码：

```yaml
accepted-state-lengths: [292, 332]
timezone: America/Los_Angeles
```

长度列表为 1–32 个不同整数（1–4096），默认 `[292, 332]` 仅为经验兼容值，不根据 Team 等套餐名称推断。`timezone` 必须为有效 IANA 名称；每个请求使用一个配置快照，面板显示和每日休眠仍使用 UTC+8。

多账号与可视化配置见 [VISUAL_CONFIG.md](VISUAL_CONFIG.md)。设置 `probe-account-mode: all-accounts` 可为所有可用 CPA 认证文件分别维护票据；`highest-priority` 仅选择当前最高优先级账号。默认 `fixed` 需要凭据路径与宿主认证列表的路径精确绑定，无法匹配时明确不可用。每个任务及其重试锁定原账号，不因认证失败切到另一账号。凭据通过 Host Auth 读取，仅在内存中使用，不展示。绑定使用凭据中的稳定 JWT 签发方/主体及工作区；无法提取稳定身份时保守绑定当前 Token 摘要，Token 刷新后重新积累票据。实验性账号路由默认关闭，只在同优先级候选中参考最近一小时的健康证据；代理传输失败或限流不作为账号降级证据。自动账号切换探测仍遵守预备窗口、休眠、暂停与全局停止。

管理面板支持同源 CPA 的 `enc::v1` 和 `enc::v2` 登录缓存；损坏缓存不会启用登录，不向其他来源转发登录密钥。

### 真实有效期（token 自证）

`X-Codex-Turn-State` 是 Fernet 认证加密 token，其结构自带 **签发时间戳**：

```
base64url → [1B 版本 0x80][8B 大端 Unix 时间戳][16B IV][160B 密文][32B HMAC] = 292 字符
```

因此 **无需依赖捕获时刻与固定定时**：直接解码 token 第 2–9 字节即可得到签发时间，加上有效期时长（`ttl-minutes`，默认 55 分钟）即为真实到期时间。状态路由台以 **UTC+8（Asia/Shanghai）** 显示每个账号/模型持久化值的：

- 签发时间（token 内嵌）
- 到期时间（签发 + 有效期）
- 真实剩余（实时倒计时，`时/分/秒`）
- 已到期时标红「已到期」徽标；到期值不再对外提供，直到获得新的健康值

> 注意：token 的 HMAC 覆盖全部字段，**不能改时间戳伪造有效期**；这里仅做解码推算展示。

## 管理面板

代理池不再提供独立公网 IP 实测或采样接口。探测历史中的代理回报地址（SOCKS5 BND.ADDR）及显隐控制保留；该地址不保证是上游看到的公网 IP。

CPA 管理页 → 插件菜单「O/对抗插件」，两个标签页：

**请求记录**
- 额外来源诊断：异账号已替换 / 异账号已剥离、来源分类、脱敏铸造账号与短指纹。
- 每请求：时间（UTC+8）、账号邮箱（默认 ***，可切换显示）、模型、上游响应模型（不一致打标）、时区处理、覆写状态徽标（已覆写 / 账号未识别 / 此账号无有效票据）、Turn-State 长度与来源。
- 请求未携带票据但已注入时直接显示“注入 N 字节”；原始请求确实有票据时保留长度对比。响应独立显示收到的长度、实际修复长度和票据更新结果，旧记录不补造更新事件。

**状态路由台**
- 模型健康状态：长度彩色徽标（符合配置策略为绿 / 不符合为橙）、来源（历史种子 / 业务观测 / 探测轨）、生成/到期时间、剩余 TTL 进度条；
- **探测控制**：「开始探测 / 停止当前轮 / 停止全部」区分本轮任务与自动预备。每行 ⏸/▶ 表示实际暂停/恢复参与状态，⟳ 排队探测该模型一次；单模型动作不解除全局停止。所有任务串行执行；
- **状态显示**：分别显示正在停止、自动预备待命、手动待命和全部停止；空闲不等于暂停。探测活动与失败标注不遮挡健康值剩余时间；
- 失败标注：红色「上次探测 N 次失败」徽标（悬停查看完整错误）；
- 探测记录与成功记录均可独立展开/折叠，默认收起；显示时间 / 模型 / 出口名称 / 结果 / 耗时 / 说明（含上游模型名）。探测记录显示最近 50 条；成功记录独立保留最近 50 次成功，不受后续失败挤出，并随状态快照恢复。旧快照只能补回其中尚存的成功记录。
- 顶部：探测轨状态胶囊、优先模型、探测成功数、最近活动。
- 标题右侧：「降智请求拒绝」全局开关（独立标签页之外，始终可见）。

## 常见问题

**Q1：为什么我固定了一个值，上游有时表现异常（延迟高、状态不再更新）？**
固定值可能与当前会话/时间窗不匹配。上游对「合法但过期」的值有时容忍、有时拒绝。建议开启探测轨以持续获得新鲜值。

**Q2：312 字节是什么？**
疑似风控降级态（模型响应一致但状态结构异常）。本插件的验收规则会拒绝它并继续重试。

**Q3：能自己改时间戳让它"更新鲜"吗？**
不能。HMAC 覆盖全部字段，任何改动都会验签失败。能通过校验的只有上游自己签发的 token。

**Q4：探测消耗什么？**
使用与业务相同的账号配额，单次为最小请求（几十 tokens 级）；仅在有效期窗口内按需触发。

**Q5：需要几个出口？**
一个也可以（默认 `direct`）。多出口的价值在于：某个出口拿到降级/无效状态时轮换到另一个出口重试。

**Q6：会不会影响已有业务流量？**
探测轨完全独立、不经 CPA 主链路；覆写逻辑只对配置的模型生效，可随时用 `enabled:false` 关闭。

**Q7：支持哪些平台？**
本插件为 Go c-shared 动态库，与平台无关：Linux `.so` / Darwin `.dylib` / Windows `.dll`（按目标平台构建）。

### 状态快照（持久化）

- 插件将面板状态（健康基线值、失败标注、疑似计数、暂停列表、降智拒绝开关、探测计数、探测轨迹与请求记录）定期写入本地 JSON 快照（原子写、权限 0600），插件重载或容器重启后自动恢复，无需重新设置。
- 默认路径：`/CLIProxyAPI/logs/.plugins/timezone-override/state.json`（可用环境变量 `LKS_TZ_STATE_FILE` 覆盖，测试用）。
- 面板确认的预备窗口和代理编辑保存在同目录的 `runtime-settings.json`，其中可能包含代理认证，不能公开或提交仓库；它不替代上述票据快照。
- **种子文件**（可选）：`/CLIProxyAPI/logs/.plugins/timezone-override/seeds.json`（`{"模型": "符合配置长度的值"}`），启动时用于补全缺失基线；由部署流程从历史记录/备份中提取，权限 `600`，不随仓库分发。
- 写入频率：状态变化后最迟 `15s` 落盘一次；`plugin.shutdown` 时立即终轮一次。
- 容量有界（200 条请求记录 + 200 条探测轨迹 + 50 条独立成功记录 + 每模型 4096 字节状态值），典型快照 < 1MB。

## 可选：单向只读状态镜像

插件可向独立 `state-mirror` 服务推送精简状态，外部访问者通过 `/state` 查看探测统计和模型健康基线。公开页面没有 CPA 管理密钥、控制按钮或控制接口；接收服务也不连接 CPA。该功能默认关闭，需要重新构建插件并显式配置推送目标。

多账号时，公开镜像按模型显示账号基线可用数量，不展示账号标识；多个账号各有有效期，不捏造一个共享倒计时。管理控制台可查看每个账号的两个槽位。

展示字段仅包含探测状态、优先模型、成功/总次数、预备窗口/串行间隔的只读数值，以及每模型的参与状态、状态长度、来源、当前/预备票据签发和到期时间、固定类型的异常标记。不包含票据正文/预览、代理地址/IP/认证、最近活动、预算说明、请求记录或探测历史。源端和接收端分别使用白名单结构与严格字段校验。

### 启动接收服务

在 `src/` 构建独立服务（不需要 CPA 或 CGO）：

```sh
CGO_ENABLED=0 go build -o build/state-mirror ./cmd/state-mirror
```

在受控位置生成一个至少 32 字节的随机专用签名密钥文件，权限设为 `0600`。将同一密钥分别提供给插件和接收端，不复用 CPA 管理密钥、不把密钥写进网页/命令行/仓库。例如将已配置好的密钥文件挂载到 `/run/secrets/state-mirror.key`：

```sh
./build/state-mirror \
  -public 127.0.0.1:8768 \
  -ingest 127.0.0.1:8769 \
  -key-file /run/secrets/state-mirror.key \
  -data /var/lib/state-mirror/state.json
```

- `8768` 只开放 `GET /state`、页面资源、`GET /state/snapshot` 和 `GET /state/events`（SSE）。没有写入或管理路由。
- `8769` 只提供 `POST /ingest`，要求 HMAC-SHA256 签名、60 秒内时间戳及完整合法快照。它应只对插件所在的私有网络开放，不能随公开网页一起反向代理。
- 数据文件只含展示白名单快照；原子写成功后才确认接收。重启恢复最后快照及排序信息，断线后的 SSE 连接直接取得完整最新状态。
- 默认同时最多 128 个 SSE 连接，慢连接有写超时。服务器时钟应同步；不同机器时钟严重偏离会导致签名或实例顺序校验失败。

### 插件端配置

在 CPA 进程/容器启动环境中配置，并确保密钥文件在该容器内可读：

```text
LKS_MIRROR_URL=http://state-mirror:8769/ingest
LKS_MIRROR_KEY_FILE=/run/secrets/state-mirror.key
```

上述 `state-mirror` 是示例 Docker 私有网络服务名。容器内的 `127.0.0.1` 指向容器自身；不要把宿主机回环地址直接照抄进另一容器。容器间部署时接收服务可在其容器内监听 `0.0.0.0:8769`，但不向公网发布该端口。HTTP 仅用于受信任本机/隔离私网；跨不可信网络应使用 HTTPS 接收入口，保留证书验证。目的地不走模型代理池或系统代理，不携带业务凭据，不跟随重定向。

配置在插件生命周期启动时读取；修改环境或密钥后需计划内重启/重新加载二进制。只有两个参数均有效才启动发送器。新增 `src/mirror.go` 与 `src/internal/statemirror/` 必须纳入插件构建源文件；不能沿用漏掉子目录的旧上传清单。

发送器每秒检查只读状态投影，变化时发送完整快照，短暂变化合并为最新状态；它是状态镜像，不是每次状态迁移的审计日志。无变化时每 30 秒心跳，网络请求最多 3 秒，失败退避至最多 15 秒并重试最新状态，不阻塞探测/业务。接收端按实例启动时间和递增序号拒绝旧状态、重复消息不刷新在线时间。发送失败不改变探测状态，网页在超过 90 秒未收到有效更新时标记数据可能过时。

网页通过接收端时间校准本地倒计时，到期自行显示过期，预备票据是否接管仍等待插件更新。四语（简中/繁中/英/俄）与纯白/羊毛纸/暗色主题在独立页面选择，默认语言/主题跟随浏览器，不依赖 CPA 登录或父页面。

### 反向代理

将 `src/cmd/state-mirror/nginx.example.conf` 中的 location 片段加入已有 HTTPS 虚拟主机即可提供 `https://<你的域名>/state`。只代理公开的 `8768` 端口，保留路径、关闭 SSE 缓冲及缓存。不要将 CPA `/v0/management/` 或私有 `/ingest` 暴露给该页面。上线须另行核实实际反代、容器网络和端口映射；示例不是部署脚本。

验证：在 `src/` 执行 `go test . ./internal/statemirror ./cmd/state-mirror`、对应 `go vet`、`go test -race -run 'TestMirror|TestReceiver|TestPublicRoutes' . ./internal/statemirror ./cmd/state-mirror`，以及 `node --test cmd/state-mirror/web/app.test.cjs web/index.test.cjs`。测试仅使用回环服务和合成状态。
